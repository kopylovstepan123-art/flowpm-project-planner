# FlowPM — описание проекта

## Назначение

FlowPM создавался как учебный проект для практики Vibe Coding и публикации веб-приложений. По продуктовой идее это лёгкий локальный планировщик проектов, похожий на Jira: пользователь хранит проекты и задачи, видит их состояние и зависимости, а AI помогает разложить большой запрос на план работ.

Это MVP для демонстрации и обучения. Автор решил не продолжать продуктовую разработку, поскольку для превращения прототипа в надёжный сервис потребовались бы значительные дополнительные усилия.

## Основные сценарии

1. Пользователь создаёт проект и добавляет задачи вручную или через быстрый список входящих.
2. Для задачи можно указать описание, проект, статус, приоритет, тип, даты, чек-лист и заметки.
3. Пользователь связывает задачи отношениями «блокирует», «зависит от» или «связана с». Пока задача-предшественник не завершена, зависимая задача отображается как заблокированная. Также приложение выделяет задачи, доступные для начала.
4. Пользователь планирует работу в календаре, перемещает задачи по датам и отслеживает состояние на панели проекта.
5. Для AI-плана пользователь вводит описание проекта, при необходимости задаёт дедлайн, число задач от 3 до 30, а также включает планирование дат и создание зависимостей. AI предлагает черновик с задачами, описаниями, статусами, приоритетами, типами, датами, чек-листами и связями. До сохранения пользователь видит предпросмотр и может применить или отменить план.
6. Для знакомства с приложением можно загрузить демонстрационные данные. Рабочее пространство можно экспортировать в JSON и затем импортировать.

## Интерфейс

- **Панель:** сводные счётчики и переход к актуальным задачам и проектам.
- **Проекты:** список и управление проектными пространствами.
- **Календарь:** обзор задач по дням, перенос задач и просмотр задач без даты.
- **Входящие:** быстрая фиксация задачи до назначения в проект.
- **Настройки:** название рабочего пространства, параметры AI, импорт и экспорт JSON.
- **Карточка задачи:** поля задачи и отображение входящих и исходящих связей.

## Технологии и архитектура

Сведения проверены по файлам опубликованной версии на 29 октября 2026 года:

- `index.html` — разметка приложения и формы.
- `style.css` — оформление и адаптивные правила.
- `script.js` — интерфейс, состояние, фильтры, связи, импорт/экспорт и запрос к AI.
- HTML, CSS и vanilla JavaScript; сборщик и сторонний фронтенд-фреймворк в опубликованной версии не обнаружены.
- Серверного приложения и базы данных в опубликованной версии не обнаружено.
- Рабочее пространство хранится в браузере под ключом `flowpm_ru_local_v1`; AI-ключ хранится отдельно в `localStorage`.
- AI-вызов отправляется из браузера к `https://api.openai.com/v1/responses`. Модель по умолчанию — `gpt-4o-mini`, её можно изменить в настройках.

## Данные задачи

В опубликованной версии используются:

- статусы: `Backlog`, `To Do`, `In Progress`, `Done`;
- приоритеты: `Low`, `Medium`, `High`, `Critical`;
- типы: `Task`, `Milestone`, `Risk`;
- типы связей: `depends_on`, `blocks`, `related`.

Состояние блокировки рассчитывается по связям: задача заблокирована, если её предшественник связан как блокирующий или как зависимость и ещё не имеет статуса `Done`.

## AI-планировщик

AI-функция принимает текстовое описание проекта, дедлайн (если задан), ограничение на число задач и настройки планирования. Приложение отправляет запрос в OpenAI Responses API и ожидает JSON с кратким описанием, задачами и связями. Ответ разбирается и нормализуется до показа пользователю. В интерфейсе также есть демонстрационная генерация плана без API.

Ключ вводится в настройках и сохраняется в `localStorage` текущего браузера. Экспорт рабочего пространства не включает ключ. Прямой запрос к API из браузера — слабое место архитектуры для публичного продукта: ключ может быть доступен коду и инструментам браузера. В промышленной версии запросы нужно отправлять через сервер, не встраивать ключ в клиент.

В AI-запрос включается не только новый текст, но и сведения о проекте, существующих задачах и связях. Поэтому при использовании AI эти данные передаются OpenAI. Для демо не следует вводить конфиденциальную информацию.

## Хранение и публикация

Данные сохраняются только в браузере пользователя. Нет регистрации, серверной синхронизации или общего пространства для нескольких пользователей. Демо-ссылка открывает само приложение; данные в `localStorage` привязаны к конкретному браузеру и профилю. Резервная копия переносится через экспорт/импорт JSON.

Опубликованная версия доступна через IPFS-шлюз: [FlowPM Demo](https://ipfs.sweb.ru/ipfs/QmNsYkFyWzoyiD14isV4MKUUmWkdD2oxvmvNNrhz13sEuG/). Исходные статические файлы получены из опубликованной версии. Подробности о том, как именно настраивалась публикация, автор пока не указал.

## Проверка и статус

Автор сообщил, что вручную проверил все функции, в том числе демонстрационные данные, переходы задач по статусам и отслеживание блокеров. Автоматические тесты в опубликованном наборе файлов не найдены, поэтому ручную проверку следует указывать как проверку автора, а не как автоматизированное тестирование.

По словам автора, проект остался MVP: дальнейшее развитие было остановлено, поскольку превращение его в полноценный надёжный продукт потребовало бы существенно больше времени.

## Ограничения и возможные улучшения

- Добавить backend, пользовательские аккаунты и совместную работу.
- Перенести ключ AI и обращения к модели на сервер.
- Добавить облачное хранение, синхронизацию и резервное копирование.
- Добавить автоматические тесты для зависимостей, статусов, импорта/экспорта и AI-ответов.
- Проверить обработку сбоев сети, некорректных данных и ошибок модели.

Это направления развития, а не реализованные функции.

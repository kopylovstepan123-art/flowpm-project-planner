# FlowPM — локальный планировщик проектов

FlowPM — учебный MVP планировщика проектов и задач, вдохновлённый Jira. Проект был создан для практики Vibe Coding и публикации веб-приложения. Его главная особенность — AI-планировщик: он превращает описание проекта в черновой план задач, сроков и зависимостей.

**Демо:** [Открыть FlowPM](https://ipfs.sweb.ru/ipfs/QmNsYkFyWzoyiD14isV4MKUUmWkdD2oxvmvNNrhz13sEuG/)

## Возможности

- Создание проектов и задач с описанием, статусом, приоритетом, типом, датами и чек-листом.
- Статусы задач: бэклог, к выполнению, в работе и готово. Типы: задача, веха и риск.
- Связи между задачами: «блокирует», «зависит от» и «связана с». FlowPM показывает заблокированные задачи и задачи, которые можно начинать.
- Панель проекта, быстрый список входящих задач и календарь с дедлайнами. Задачи можно перемещать между датами.
- Загрузка демонстрационных данных, а также импорт и экспорт рабочего пространства в JSON.
- AI-планировщик: по текстовому описанию предлагает задачи, даты, чек-листы и связи. Можно задать срок проекта, число задач, включить планирование по датам и создание зависимостей. Перед добавлением план показывается на предпросмотре.
- Режим демонстрации AI без API-запроса.

## Как устроено приложение

По опубликованной версии это клиентское веб-приложение на HTML, CSS и обычном JavaScript. В нём не обнаружены Java, серверная часть, база данных или сторонний JavaScript-фреймворк. Данные проектов, задач, связей и входящих хранятся в `localStorage` текущего браузера.

AI-планировщик по умолчанию использует `gpt-4o-mini` и обращается напрямую из браузера к OpenAI Responses API. Ключ вводится пользователем и хранится локально отдельно от файла экспорта. План сначала проходит проверку и показывается пользователю; добавление в проект выполняется после подтверждения.

При запуске AI-планировщика введённое описание, сведения о проекте и существующих задачах отправляются в OpenAI. Не используй в этой демонстрационной версии конфиденциальные данные.

## Запуск

Веб-приложение состоит из `index.html`, `script.js` и `style.css`. Их нужно хранить в одной папке и разместить на статическом веб-сервере. Для функций AI пользователь добавляет собственный API-ключ в настройках; без ключа доступен демонстрационный режим.

## Проверка

Автор проекта сообщил, что вручную проверил функции приложения, в том числе загрузку демонстрационных данных, изменение статусов и работу отслеживания блокеров. В доступном снимке проекта автоматизированный набор тестов не обнаружен.

## Ограничения и дальнейшее развитие

Это учебный MVP, а не готовый командный сервис. У приложения нет учётных записей, серверного хранения, синхронизации между устройствами и совместной работы. Данные остаются в браузере; очистка его хранилища может привести к их потере, поэтому предусмотрен JSON-экспорт.

В демонстрационной реализации AI-ключ используется на стороне браузера. Такой способ подходит только для личного прототипа: для публичного продукта запросы AI нужно перенести на сервер, а ключ хранить там. Чтобы превратить MVP в полноценный продукт, потребуются отдельные разработка, проверка безопасности, серверное хранение и автоматические тесты.
